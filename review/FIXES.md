# 稳定性修复说明

日期：2026-10-05。对应修复前审查报告的 F01–F19。本次修改业务源码并更新 dist/GameSwitcher.exe，原版备份为 dist/GameSwitcher.before-stability-fix.exe；未上传 GitHub Release，也未修改用户正在使用的配置或自启注册表。

## 主要改动

| 原问题 | 修复方式 |
| --- | --- |
| F01 / F03 默认强杀、进程树波及 | 删除 taskkill 路径，只请求正常关闭本轮捕获的窗口；超时或取消时保留应用 |
| F02 同名跨目录误匹配 | 完整路径匹配；路径排除与旧文件名规则的适用范围分开 |
| F04 / F05 关闭后才保存、部分关闭不记录 | 关闭前原子提交所有目标；关闭、未关闭和中断均保留恢复信息 |
| F06 / F09 配置损坏与缺乏校验 | 缺文件与损坏/不可读文件分开处理；校验结构、字段、有限超时范围；首次必须明确捕获基线 |
| F07 未确认恢复就删记录 | 观察新窗口持续存在后才确认；辅助进程、另一目录或不同文档的进程不会单凭 exe 被当成已恢复 |
| F08 退出中断任务 | 非 daemon 操作线程；退出取消后续操作、关闭工具自身的提示框、等待收尾，最后释放单实例锁 |
| F10 多实例上下文丢失 | 每个独立窗口进程保留独立记录、参数、工作目录；Shell 启动回退保留参数和 cwd |
| F11 新 PID 被加入强杀 | 不重新扩大关闭集合；关闭前核对 PID、创建时间、exe、用户和会话 |
| F12 清空失败静默、模式不一致 | 原子写空状态，错误向上传播；使用独立 mode 状态，空恢复清单也可处于游戏模式 |
| F13 排除列表旧数据、15 项限制 | 明确刷新入口，列出全部路径；显示规则与实际排除规则一致 |
| F14 UI 扫描及菜单竞争 | UI 使用缓存；读写、扫描串行在后台执行；通过消息队列在 UI 线程更新原生菜单和图标 |
| F15 吞掉错误 | 未完整扫描时抛异常；无法识别进程时保留目标；日志记录关闭、启动和确认失败 |
| F16 处理范围误导 | 限制当前用户和登录会话，保护自身祖先；文档明确只覆盖识别到的可见窗口 |
| F17 构建与验证缺失 | 固定运行/构建依赖；移除任意 DLL 关键词裁剪；新增 Windows CI、原生和 EXE 自检 |
| F18 文档与实现不同 | 中英文说明统一为正常关闭和启动记录恢复，取消秒杀、通用自动保存及完整现场恢复承诺 |
| F19 日志/快照维护 | 日志轮转；基线只保存 exe/name，不保存命令行、窗口标题和 cwd |

恢复启动前还会写入 restore_attempted 标记。启动未确认或操作中断后，普通“恢复”不会自动再次创建进程。先核对程序，再用“重新尝试未确认启动”进行显式重试。

状态文件使用 version 2、mode 和 apps。旧列表快照兼容读取，下一次写入会迁移。新版同时持有同用户配置目录的文件锁及旧版会话互斥，以降低升级期间的并发写入风险。不要在新版迁移后继续运行旧版。

## 使用上的变化与剩余边界

1. 目标应用可以显示自己的保存提示。超时后不会自动强杀，需要用户处理；关闭窗口也可能让应用按其设置继续后台运行。
2. 恢复保存的是启动信息，不能恢复未保存文档内容或保证同一进程中的全部标签/工作区。不同进程实例已分别保存，单进程多文档仍依赖应用自身会话恢复。
3. 可见窗口持续存在只是启动确认，不能证明应用内部文档加载正确或保证其随后不会崩溃。无新窗口、启动慢、UAC/应用额外确认、内部辅助参数和失效工作目录会保留记录。
4. 部分窗口已经关闭、另一些原窗口仍存在时，保留记录并提示人工核对，避免为了补窗口再次打开已有文档。
5. 不支持清空所有无窗口后台程序；管理员或无法读取启动上下文的程序保留运行。新版应用识别增加身份检查，首次扫描较旧版慢，但扫描不在托盘 UI 线程执行。
6. 构建保留完整导入依赖，包体会大于原先宣传的 7.58 MB。体积和 hash 以本地制品自检为准。
7. Windows CI 已添加，本次只验证了本机运行和构建，尚未执行远程 CI，也未对实际 Office/浏览器会话和长时间连续使用作兼容性保证。
