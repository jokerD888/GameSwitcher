# 模式 B 修复：完整基线、逐进程保护与独立恢复

日期：2026-10-28。此版本恢复模式 B，不再用停用功能代替修复。

## 针对已确认问题的修改

| 问题 | 当前实现 |
| --- | --- |
| 开机捕获仅记录可见窗口，实际基线为 [] | 捕获所有可读取的当前用户/会话进程路径；保存带来源版本的完整基线；旧窗口基线和空基线不能进入 B |
| 后代绕过基线与排除 | 每个实际候选都校验基线、排除、身份、用户/会话与系统保护；含保留后代时保留候选树 |
| 远控输入程序被处理 | GameViewer 等远控/输入程序、安装目录和依赖树保留；受保护应用新产生的辅助进程也保留 |
| 基线 Explorer 可能保护所有新程序 | 区分启动器与应用依赖祖先，普通新应用仍可以进入候选 |
| 父子可见窗口造成重复挂起 | 全局 PID/创建时间/路径去重，每个原生对象只暂停一次 |
| PID 列表没有正确写入快照 | 根记录先持久化 suspend_id，独立事务逐项保存完整进程身份、阶段及窗口状态 |
| PID 复用风险 | 进程句柄打开后，通过句柄读取创建时间、完整路径验证；恢复使用原句柄或重新核对完整身份 |
| 一次卡死无法恢复 | 独立守护负责恢复；12 秒输入确认超时、5 秒 UI 心跳超时、Ctrl+Alt+F12 或主进程退出触发恢复 |
| 退出在消息线程同步解冻且与 worker 竞争 | 先取消/等待 worker，再在退出线程请求守护恢复；不在原生菜单消息线程执行恢复 |
| 工作集强制裁剪 | 与 B 分离：B 不执行 EmptyWorkingSet、不配置页文件，不再承诺内存 0 MB 或全量 SSD 置换 |
| 恢复失败也清空记录 | 守护未确认完成时保留事务引用；恢复失败不重新启动仍在挂起的进程 |
| 放弃时终止程序 | 放弃前释放本工具拥有的挂起，不终止应用 |

## 实现组织

- core.py：完整进程清单、基线采集、关闭和恢复入口；正常关闭与挂起各自保留语义。
- suspension.py：只读保护计划、挂起事务、父进程客户端、独立守护、身份恢复与完成记录协调。
- winprocess.py：64 位 Win32 声明、句柄身份验证、事件、热键及本工具 GUI 的响应检测。
- main.py：双模式入口、可选目标预览、12 秒输入确认，以及安全退出。
- storage.py：完整基线来源标记、挂起事务引用校验和原子持久化。

守护不再递归追逐新 PID。它复核固定计划后打开并持有目标句柄，提前保存窗口位置，最小化窗口，然后对去重后的进程逐项暂停。用户确认后由托盘消息循环响应驱动心跳。超时或主进程退出时，守护逆序解除自己添加的挂起并恢复窗口。

异常退出后，恢复只使用事务中保存的身份，保留不确定状态。第三方调试器额外添加的挂起不会被反复解除。完整 Windows 重启后进程内存已经消失，记录退回启动信息恢复；不声称能够找回关机前未保存内容。

## 升级后的操作

1. 退出旧版，运行新版。
2. 若仍有上次 PID-only 记录，先按提示恢复/处理旧记录。
3. 在干净环境重新选择“捕获完整进程基线”。当前旧空基线不会自动被当成有效完整基线。
4. 可先预览模式 B 的目标，再进入模式 B；暂挂起后 12 秒内确认键鼠和桌面正常。
5. 结束游戏点击恢复；紧急情况按 Ctrl+Alt+F12。

模式 B 仍需要目标软件适合暂停。守护不能保证覆盖内核故障、整机断电、同时结束托盘与守护，或所有外部调试/注入行为。物理内存回收交给 Windows；本次不对真实办公软件做破坏性输入卡顿复现。
